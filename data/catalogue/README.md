# catalogue data

Swappable, versioned Catalogue files. Build against a public stand-in until Arun Paint
Industries measured values arrive; their data then drops in with no code change.

The file is the **source of truth**. The service loads it into SQLite at launch for fast search and
grouping (`services/inference/spectrapaint/catalogue/`), and never writes back to it. One Catalogue
is loaded at a time — see [design-decisions.md §7](../../docs/design-decisions.md).

---

## What is here

| File | |
|---|---|
| `public-stand-in-2026-08-19.json` | The stand-in Catalogue the app loads today: 1,159 Shades across 13 Shade Families. Generated by [`tools/generate_stand_in_catalogue.py`](../../tools/generate_stand_in_catalogue.py) by sampling the Lab space — realistic in shape and size, **not** in accuracy. Do not hand-edit it; change the generator and re-run. |

## File format

**JSON**, one file per Catalogue version, named `<catalogue_id>-<version>.json`.

```json
{
  "catalogue_id": "public-stand-in",
  "catalogue_name": "Public stand-in Catalogue",
  "version": "2026-08-19",
  "source": "Where the values came from, in one line",
  "colour_space": {
    "space": "CIELAB",
    "reference_white": "D65",
    "observer": "2"
  },
  "shades": [
    {
      "shade_code": "PS-1010",
      "name": "Morning Linen",
      "shade_family": "Neutrals",
      "lab": { "l": 92.4, "a": 1.2, "b": 5.8 },
      "finishes": ["matte", "satin"]
    }
  ]
}
```

### Header fields

| Field | Required | Meaning |
|---|---|---|
| `catalogue_id` | yes | Stable machine identity for **which** Catalogue this is. Recorded on every Render, so a saved Consultation still says what `PS-1010` referred to (design-decisions §7). Lowercase, `[a-z0-9-]`. |
| `catalogue_name` | yes | What the Dealer is shown. |
| `version` | yes | Changes whenever any value changes. Free-form string, compared only for equality — a date or a manufacturer's revision number both work. |
| `source` | no | Provenance, for whoever asks later where the numbers came from. |
| `colour_space` | yes | Pinned explicitly, never left to a default. V1 accepts only `CIELAB` / `D65` / `2` — the spec pins Lab reference white to D65, 2° observer, and a file measured against D50 would shift every conversion. Present so a mismatch **fails loudly** at load instead of silently rendering wrong colours. |

### Per Shade

| Field | Required | Meaning |
|---|---|---|
| `shade_code` | yes | The Dealer-facing identifier, e.g. `AP-2140`, exactly as printed on the Fandeck chip. Unique within the file, and the primary search key. Case is preserved for display; lookup is case-insensitive, because the Dealer types what the Customer reads aloud. |
| `name` | yes | The marketing name. Searchable on partial input. |
| `shade_family` | yes | The browsing group — neutrals, blues, earth tones. Defined by the manufacturer, not by us. |
| `lab` | yes | The colour value: `l` in 0–100, `a` and `b` in −128–127. |
| `finishes` | no | Matte, satin, gloss. **Metadata only in V1** — shown beside a Shade, never used in a render (design-decisions §8). Defaults to empty. |

Field names are `snake_case`, matching the HTTP contract (conventions §4), so no field is renamed on
its way to the UI.

## Swapping the Catalogue

Point the service at a different file and restart it — no code change, which is the acceptance
criterion this format exists to satisfy. Where the path comes from is documented in
[`services/inference/spectrapaint/catalogue/README.md`](../../services/inference/spectrapaint/catalogue/README.md).

A malformed or unreadable file **fails at launch**, not mid-Consultation: the Dealer finds out before
a Customer is standing at the counter (conventions §5).

## Licensing

Values in a committed stand-in file must be free to redistribute, and its `source` must say where
they came from. Manufacturer-measured data is not committed here unless we have permission to.
